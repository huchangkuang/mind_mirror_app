## ADDED Requirements

### Requirement: 主区展示底部双 Tab

已登录用户进入 `(main)` 后，系统 MUST 在屏幕底部展示 Tab 栏，且仅包含两个 Tab：**测试首页**与**我的**。

#### Scenario: 用户已登录进入主区

- **WHEN** 用户会话状态为已认证并进入 `(main)`
- **THEN** 界面 MUST 显示底部 Tab 栏，且可见恰好两个 Tab，分别为「测试首页」与「我的」（或语义等价的展示文案）

### Requirement: 测试首页 Tab 承载测评入口列表

「测试首页」Tab MUST 展示与变更前主列表一致的核心能力：展示可用测评列表、支持进入各测评流程（如 MBTI、城市匹配、宇宙精神原色等），并保留列表加载、错误与重试等既有行为（除非另有专项变更）。

#### Scenario: 用户在测试首页查看列表

- **WHEN** 用户选中「测试首页」Tab
- **THEN** 系统 MUST 展示测评列表区域，且用户能够发起进入某一测评流程的导航

### Requirement: 我的 Tab 承载个人中心

「我的」Tab MUST 承载个人中心功能，包括与变更前 `profile` 一致的账户与资料相关能力（例如查看/修改昵称、修改密码、退出登录等，以当前实现为准）。

#### Scenario: 用户打开个人中心

- **WHEN** 用户选中「我的」Tab
- **THEN** 系统 MUST 展示个人中心界面，且用户能够执行退出登录或资料相关操作（与实现可用的功能一致）

### Requirement: 子页面堆叠在对应 Tab 的栈上

从「测试首页」进入的测评子页面（答题、结果、历史等）MUST 以栈形式覆盖在「测试首页」之上，返回时回到进入前的列表或上一级；「我的」内若有二级页（若未来增加）同理。用户切换 Tab MUST 保留各 Tab 内栈的独立状态（与 React Navigation 默认行为一致）。

#### Scenario: 从测试首页进入测评再返回

- **WHEN** 用户在「测试首页」进入某一测评子流程并执行返回操作直到回到 Tab 根
- **THEN** 用户 MUST 仍停留在「测试首页」Tab，且底部 Tab 栏保持可见（除非当前实现故意隐藏 Tab 栏的特定屏，此类情况须在实现中明确并在此规格中保持一致）

### Requirement: 未登录用户不得进入 Tab 主区

系统 MUST 在未认证会话下不展示上述 Tab 主区，并继续采用既有跳转至认证流程的行为（例如重定向至登录页）。

#### Scenario: 未登录访问主区

- **WHEN** 用户未登录并尝试进入 `(main)`
- **THEN** 系统 MUST NOT 将用户置于已登录 Tab 主区，并 MUST 按现有逻辑引导至登录或注册流程
